# Proposal: add-lan-device-registry

## Why

项目定位已从"智能家居终端"调整为"局域网设备管理 Agent"（README 改版，commit a4997a7）：管理家庭内网（自动检测到的 /24 网段），而非控制家电。当前前端与该定位脱节——「设备」tab 是智能家居占位页，「仪表盘」整页是智能家居假数据演示（统计卡、7 日语音指令图、服务状态、最近活动），项目中没有任何设备发现、注册、存储的真实链路。

需要建立内网设备的"配对—注册—展示—维护"闭环：注册流程类似电脑配对蓝牙设备——单击按钮进入配对页面，触发嗅探发现新设备，人工确认后加入已注册列表；仪表盘随后展示已注册设备的名称、IP、开放端口（含服务、多级展开）与在线状态。

## What Changes

- **删除「设备」tab**：移除顶栏 tab 与 `/devices` 占位路由
- **「仪表盘」整页替换**：改为「已注册设备」列表（在线/离线徽标、设备名称、IP 地址、端口三级展开：设备 → 端口 → 服务详情），删除全部智能家居假数据组件
- **新增「设备配对」页面**（独立路由 `/discover`，从仪表盘按钮进入）：
  1. 触发后端对本地网段的 ping 嗅探（第一步，快），列出存活且未注册的主机（以 IP 为单位）
  2. 人工勾选、确认/修改预填名称后注册
  3. 注册动作立即返回；被选设备的端口扫描在**另一个线程**异步进行（nmap top 1000 端口），完成后端口数据落库并在列表中可见
- **后端新增设备注册表与 API**：SQLite 新增 devices / device_ports 表；设备发现、注册、重命名、移除、在线状态刷新的 REST API（均需登录，不限角色）
- **启动流程增强**：项目启动时自动获取当前网卡（DHCP 分配的 IP）所在网段，console 日志明确打印检测到的网段；同时检测 nmap 可用性（缺失时降级：仍可 ping 发现与注册，仅端口扫描不可用）
- **`.env` 新增配置**：仪表盘在线状态轮询间隔 `LAN.PING_INTERVAL`（默认 5s，最小 1s）

## Capabilities

### New Capabilities

- `device-registry`：内网设备的自动发现（ping 嗅探）、人工确认注册（蓝牙配对式流程）、端口/服务展示（三级展开）与在线状态维护（进入刷新 + 前端定时轮询）

## Impact

- **后端**（`src/web/backend/`）：新增 devices 路由与服务层、网段检测模块、ping/nmap 工具封装、异步扫描线程；启动流程加网段检测与依赖检查
- **前端**（`src/web/frontend/`）：路由表改动（删 `/devices`、增 `/discover`）、DashboardView 整页重写、新增配对页组件；轮询定时器生命周期管理
- **数据库**：新增 devices、device_ports 两张表（纯新增，无迁移）
- **环境依赖**：服务器需安装 nmap 并可在 PATH 或 `NMAP_PATH` 中找到；ping 依赖系统命令（Windows 无需管理员权限）
- **范围外（Non-goals）**：设备控制（下发指令）、自动化任务、定时后台扫描、设备凭证管理——后续变更再议
